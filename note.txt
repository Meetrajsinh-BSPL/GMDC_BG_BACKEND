Project Overview

Purpose: Extract structured Bank Guarantee (BG) fields from uploaded PDF documents, validate/extract BG metadata, and optionally query ICICI Bank eBG API for matching records.
Business problem solved: Automates BG ingestion and validation for procurement/finance: reduces manual extraction of BG number, amounts, dates, issuing bank, beneficiary (e.g., GMDC), and validates against bank records.
Major features:
PDF text extraction cascade (pdfplumber, PyMuPDF, pypdf, OCR) — pdf_extract.py.
Vision-based multimodal extraction via OCI Generative AI (cohere.command-a-vision) — vision_extractor.py.
Text-based LLM extraction via OCI Cohere model — cohere_client.py.
Regex heuristics and normalization for BG-specific fields — heuristics.py, normalizers.py.
ICICI eBG API client with AES/RSA encryption helpers — icici_client.py, crypto_utils.py.
Flask REST API exposing extraction, validation and ICICI query endpoints — app.py.
Architecture Analysis

Overall pattern: Small monolith Flask API with layered responsibilities:
Presentation layer: app.py (HTTP endpoints, request validation, CORS, Swagger).
Extraction layer: vision_extractor.py, cohere_client.py, pdf_extract.py, field_builder.py.
Heuristics/normalization layer: heuristics.py, normalizers.py, validation.py.
Integration layer: icici_client.py, crypto_utils.py.
Config/secrets: config.py.
Runtime components:
Flask app (exposes endpoints).
OCI GenerativeAI client for vision/text.
Optional OCR via Tesseract/Pillow for fallback.
Outbound HTTPS to ICICI with encrypted payloads.
Design patterns used:
Façade for external API (thin client) — icici_client.query.
Strategy/fallback pipeline for extraction: vision → LLM text → heuristics → OCR.
Utility modules for normalization (pure functions).
Small functional decomposition; not heavily object-oriented.

Data Flow (high level)

Client uploads PDF to /extract-bg-fields or /validate-upload (app.py).
app reads bytes → extract_text_from_pdf ([pdf_extract.py]) to get full_text + last_pages_text (cascade).
build_merged_fields ([field_builder.py]) attempts:
Call extract_bg_fields_vision ([vision_extractor.py]) — image render + OCI vision chat → JSON.
If vision fails, fall back to cohere_client.extract_bg_fields using raw text.
Heuristics/regex augment from [heuristics.py], normalizers from [normalizers.py].
For validation endpoints, icici_client.query is called with encrypted session key and AES-encrypted payload ([crypto_utils.py] used for AES + RSA).
ICICI returns encrypted fields; icici_client decrypts JSON fields to plaintext and returns to app.
validation.py performs field-level matching (amount/date/id/name) between extracted fields and ICICI API response.
Important design choices & implications

LLM-first vision approach: favors accuracy for structured fields but depends on OCI config & quota.
Multi-stage fallback improves resilience (vision → text LLM → heuristics → OCR).
Cryptography implemented per ICICI spec (PKCS#1v1.5) — sensitive to cert correctness.

API surface (endpoints)

app.py endpoints:
GET /health — health.
POST /extract-bg-fields — upload PDF → extraction (vision preferred).
POST /query-icici — query ICICI by corpId, fromDate, toDate, attachmentRequired, referenceNumber optional.
POST /validate-upload — end-to-end: upload PDF, extract, query ICICI by extracted BG number, return validation results.
Optional debug: /test-encryption (enabled by ENABLE_DEBUG_ENDPOINTS).
Request/response shapes documented in Swagger config in app.py.
Validation, middleware, error handling

API key enforcement via decorator _require_api_key in app.py.
File validation for PDF uploads in _validate_pdf_upload.
Error handlers: 413 for file-too-large.
Exceptions in extraction/clients are caught and returned with error messages; ICICI failures produce structured JSON (status codes preserved).
Logging with logging module, exceptions are logged with stack trace in critical paths.

Code Quality Review

Strengths:
Clear separation of concerns (extraction vs normalization vs integration).
Robust multi-stage fallback strategy (vision → text LLM → heuristics → OCR).
Good logging and defensive error handling.
Swagger documentation embedded for endpoints.
Weaknesses / code smells:
Flat module layout (many modules at repo root) — can be reorganized into a package (e.g., gmdc_bg_api/).
No tests / no automated test harness present.
Hard to mock OCI/ICICI clients for unit testing in current layout.
Some duplicated expected keys lists across vision_extractor.py and cohere_client.py.
Technical debt:
Lack of README, contributing docs, and tests.
Environment setup and secrets handling rely on env files; recommend documenting .env.example fields.
Security concerns:
Crypto handled appropriately but ensure ICICI_CERT_PEM and ICICI_API_KEY are stored securely (not in repo).
DEBUG_ENDPOINTS can expose sensitive round-trip encryption testing — must be disabled in production.
Swagger UI exposed at /apidocs/ could be a data leak if behind auth.
Ensure TLS and network egress is controlled in deployment (ICICI endpoints).
Performance concerns:
Rendering pages and API calls to OCI are potentially slow (vision model timeouts configured; heavy CPU for PyMuPDF/Pillow/OCR). Consider async workers or background jobs for heavy loads.
MAX_CONTENT_LENGTH mitigates huge uploads, but consider streaming large PDFs.

Change Impact Guide

Safest to modify:
normalizers.py (pure functions) — unit-testable, low risk if tests added.
heuristics.py — changes expected to improve extraction; ensure tests against sample PDFs.
Logging levels and message formats in app.py.
High-risk files:
crypto_utils.py and icici_client.py — any change affects encryption/integrity of ICICI requests and may break production integration.
vision_extractor.py, cohere_client.py — changes alter LLM behavior; can degrade extraction accuracy or break JSON parsing.
app.py endpoint flows — affects inputs/outputs and error handling; must preserve contract.
Dependencies to check before change:
config.py env var names and defaults — changing names will affect deployments.
Keys/expected fields repeated across modules (EXPECTED_KEYS) — update in both vision & cohere clients if schema changes.
Cryptography library versions — ensure compatibility with cryptography API.
Potential side effects:
Changing normalization rules may alter BG number shapes causing ICICI queries to fail.
Updating LLM prompt or model ID can change output JSON format; add robust parsing and validation.
Tweaking PDF rendering zoom or page limits affects image sizes and LLM input length/cost.
